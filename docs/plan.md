# QuantAI 指数/ETF 择时项目实施方案 v2

> 更新日期：2026-04-12  
> 当前目标：从“通用量化平台”收敛为“指数择时 / ETF择时研究系统”  
> 实施节奏：**先数据获取，再量化研究**

---

## 1. v2 目标调整

### 1.1 项目目标收敛

v2 不再把重点放在“股票通用交易平台”，而是聚焦到更清晰的研究对象：

- **指数择时**
  - 如沪深300、中证500、中证1000、中证A500、创业板指、上证50等
- **ETF 择时**
  - 如沪深300ETF、500ETF、创业板ETF、黄金ETF、纳指ETF等

选择指数 / ETF 择时的原因：

- 数据噪声更低，样本更稳定
- 更适合单资产或少量资产的日线级择时研究
- 更容易把“研究信号”直接映射到 ETF 交易执行
- 可以充分复用当前 `quant-ai` 已有的指数 / ETF 行情与 K 线能力

### 1.2 后端模块抽象

v2 不再强调拆成两个独立平台，而是把现有后端能力抽象为两个大的模块，并继续保持单仓库、统一工程管理。

#### A. 数据获取模块（先做）

职责：

- 资产池管理（指数 / ETF / 成分股）
- 行情抓取与增量更新
- 特征原始数据准备
- 调度任务、数据质量、落库
- 对研究层输出稳定的“宽表 / 因子输入表”

#### B. 量化研究模块（后做）

职责：

- 因子计算
- 特征工程
- 信号生成
- 模型训练与评估
- 回测与样本外验证
- 输出最终择时信号

**执行顺序**：

1. 先把数据获取模块做稳
2. 再把量化研究模块做深

## 3. v2 的数据策略

## 3.1 核心原则

对于 v2，数据策略要遵循两个原则：

1. **优先使用稳定免费渠道**
2. **免费渠道不稳定的特征，不作为 P1 依赖，而是用现有行情数据先构造替代特征**

也就是说：

- P1 不追求“数据最全”
- P1 追求“数据闭环先跑通”

## 3.2 核心行情数据

### 推荐来源

| 数据 | 主来源 | 备用来源 | 说明 |
|---|---|---|---|
| A股日线 | Tushare | AKShare | 当前已接入 |
| 指数实时 / K线 | 腾讯财经 | AKShare | 当前已部分接入 |
| ETF 实时 / K线 | 腾讯财经 | AKShare | 当前已部分接入 |
| 股票列表 | Tushare | AKShare | 当前已接入 |

## 3.3 4 类新增特征的数据可得性判断

### 1. 市场情绪 / 市场宽度

目标特征：

- 上涨家数 / 下跌家数
- 涨停 / 跌停家数
- 中位数收益
- 市场成交额
- 新高 / 新低家数
- 行业扩散度

**判断**：

- 免费渠道有，但稳定性一般
- **P1 推荐优先用已有股票日线自己衍生**

即便不依赖第三方另类接口，也可以先从 `daily_quotes + stocks` 派生出：

- 当日上涨家数 / 下跌家数
- 全市场平均涨跌幅 / 中位数涨跌幅
- 高换手股票比例
- 大盘 / 中小盘相对强弱
- 行业级涨跌扩散指标

**结论**：  
P1 可以直接开做，不依赖额外付费数据。

### 2. 估值与资金数据

目标特征：

- PE / PB 历史分位
- 主力净流入
- 北向资金
- 融资融券余额

**判断**：

- 免费渠道存在，但稳定性与维护成本都偏高
- 不建议把这一类数据作为 P1 的主依赖

**结论**：

- P1 不纳入核心交付
- P2 可作为增强特征逐步接入

### 3. 宏观数据

目标特征：

- CPI
- PMI
- 利率
- M1 / M2
- 社融

**判断**：

- 免费来源可找，但时效性和结构稳定性一般
- 对日线择时有帮助，但不是第一优先级

**结论**：

- P1 不做硬依赖
- P2 / P3 作为低频增强特征接入

### 4. 指数 / ETF / 板块信息列表

目标数据：

- 指数列表
- ETF 列表
- 板块列表
- 指数-ETF 映射
- 指数 / ETF 标签

**判断**：

- 免费渠道可行
- 这类数据是 v2 的核心基础数据，应该优先补齐

**结论**：

- P1 必做
- 先获取列表，再逐个获取历史行情

## 3.4 v2 数据策略结论

P1 的最优策略是：

- 以**已有 OHLCV / 指数 / ETF 行情**为核心
- 优先把**指数 / ETF / 板块资产池**建完整
- 宽度类特征尽量自己派生
- 资金 / 估值 / 宏观先不作为刚性依赖

## 4. v2 实施路线图

## P1：数据获取模块（先做，2-3 周）

**目标**：完成“指数 / ETF 择时研究”所需的数据底座抽象与统一。

### P1.1 后端模块边界抽象

把当前后端逻辑抽象成两层：

- `data_module`
  - 资产池管理
  - 数据抓取
  - 特征原始表
  - 调度
- `research_module`
  - 因子、模型、回测

建议先**模块抽象 + 目录分层**，不做独立服务拆分。

### P1.2 统一研究资产池

新增并维护以下研究对象：

- 指数池
- ETF池
- 指数-ETF映射表
- 板块 / 主题标签表

建议落库为：

- `asset_universe`
- `asset_tags`
- `asset_mapping`

### P1.3 统一行情表与状态表

建议将研究资产统一成：

- `asset_daily_quotes`
- `asset_data_status`

先不急着推翻现有 `daily_quotes`，可以先通过兼容层过渡。

### P1.4 市场宽度派生特征

基于已有股票日线数据派生：

- 上涨家数 / 下跌家数
- 平均涨跌幅 / 中位数涨跌幅
- 高换手占比
- 新高 / 新低比例
- 行业扩散度

形成第一版：

- `market_breadth_features`

### P1.5 P1 验收标准

完成以下能力即视为 P1 完成：

- 指数 / ETF / 板块列表可自动更新
- 指数 / ETF 日线可批量拉取
- 市场宽度类派生特征可日更
- 数据模块与研究模块职责边界清晰

---

## P2：基础因子研究模块（2-3 周）

**目标**：把当前“规则策略平台”升级为“因子研究平台”。

### 重点任务

1. 因子库升级
   - 接入 TA-Lib
   - 保留现有 13 个技术因子
   - 引入 Alpha101 / Alpha158 子集

2. 因子评估框架
   - 因子收益相关性
   - 稳定性
   - 分阶段表现
   - 样本外一致性

3. 研究标的切换到指数 / ETF
   - 先以 3-5 个主标的做研究
   - 如：沪深300 / 中证500 / A500 / 创业板 / 黄金ETF

### P2 交付结果

- 可批量生成因子
- 可批量评估因子
- 能筛出一批基础有效择时信号

---

## P3：特征工程与简单模型（2-3 周）

**目标**：建立第一版“数据驱动择时模型”。

### 重点任务

1. `tsfresh` 特征提取
2. 标签工程
   - 未来 5 / 10 / 20 日方向
   - 未来收益率分桶
3. `FeatureSelector`
4. `Lasso` / `LightGBM`
5. Walk-forward 回测

### P3 交付结果

- 有一版可重复训练的择时模型
- 输出概率型信号
- 能与现有回测系统联动

---

## P4：自动挖掘与高级模型（3-4 周）

**目标**：把研究系统升级成真正的“择时挖掘机”。

### 重点任务

1. GP 自动表达式挖掘
   - `gplearn` / `DEAP`
2. 多目标适应度函数
   - 收益
   - Sharpe
   - 回撤
   - 稳定性
3. 深度学习增强
   - LSTM / Transformer
4. 全流程串联
   - 数据更新
   - 因子生成
   - 模型训练
   - 信号输出
   - 回测评估

### P4 交付结果

- 自动发现择时规则
- 研究-生产一体化流水线

---

## 5. 当前建议的实施优先级

接下来建议严格按下面顺序推进：

1. **先完成 P1 数据模块**
2. **再做 P2 因子研究**
3. **然后做 P3 模型融合**
4. **最后做 P4 自动挖掘**

不建议当前阶段继续优先做：

- 更多 UI 页面
- 更多交易端功能
- 深度学习模型
- 实盘接入

这些能力不是当前 v2 的主矛盾。
