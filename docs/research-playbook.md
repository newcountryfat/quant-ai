# QuantAI Guardian 研究板块实操手册

> 适用版本：当前仓库 `2026-04-26` 状态  
> 适用范围：Web UI「研究」页 + 后端 P2 因子研究接口  
> 配套页面：`研究`、`模型`、`回测`  
> 推荐阅读顺序：本手册 -> `docs/http/p1-backend.http` -> `docs/api-reference.md`

---

## 1. 这份手册解决什么问题

当前项目里的「研究」板块，负责把某个标的的日线行情转换成可研究的因子，并回答三个核心问题：

1. 这个标的在指定区间里，系统能算出哪些因子。
2. 这些因子对未来收益方向有没有预测力。
3. 哪些因子值得继续送去「模型」板块做训练和择时。

这份手册不讲泛化量化理论，只讲当前项目里“实际能怎么用”。

---

## 2. 当前项目现状

基于当前代码，研究板块已经具备以下能力：

- 因子库浏览
- 单标的全因子计算
- 因子结果持久化查询
- 因子预测力评估
- 因子 Walk-Forward 样本外验证
- 标签生成预览
- 特征筛选

当前前端入口：

- 研究页：`web_ui/index.html` 中的 `page-research`
- 对应交互逻辑：`web_ui/js/research.js`

当前后端核心：

- 因子与研究流程：`services/strategy_service/main.py`
- 因子库：`services/strategy_service/factor_mining/library.py`
- 特征筛选：`services/strategy_service/ml/feature_selector.py`

## 3. 研究板块和模型板块的边界

建议这样理解：

- `研究`板块：回答“什么因子可能有用”
- `模型`板块：回答“怎样把这些因子组合成稳定信号”

实际工作流通常是：

1. 先在研究页完成因子计算、评估、Walk-Forward、标签预览、特征筛选。
2. 再去模型页训练 `LightGBM` 或 `Lasso`。
3. 最后视情况进入 `GP` 挖掘或 `Pipeline`。

如果前面的研究结果很差，不建议直接进入模型训练。

## 4. 使用前提

在进入研究板块之前，必须先满足两个前提。

### 4.1 服务已经启动

推荐启动方式：

```bash
./venv/bin/python scripts/init_db.py
./venv/bin/python main.py
```

启动后确认：

- `http://localhost:8000/health` 正常返回
- `http://localhost:8000/` 可以打开前端页面

### 4.2 标的已经有日线数据

研究页不会替你自动补齐全部历史数据。  
如果底层没有数据，因子、标签、评估都会失败或返回空结果。

先用以下任一方式补数：

```http
POST /api/v1/data/update
```

示例：

```json
{
  "symbol": "sh000300",
  "start": "2025-01-01",
  "end": "2026-04-12"
}
```

可先用这个接口检查数据状态：

```http
GET /api/v1/data/sh000300/info
```

结合当前项目方向，建议优先研究以下标的：

- `sh000300`：沪深 300
- `sh000905`：中证 500
- `sh000852`：中证 1000
- `sh510300`：沪深 300 ETF
- `sh510500`：中证 500 ETF

不建议一开始就拿随机个股做研究，原因有两个：

- 当前项目方向已经收敛到“指数 / ETF 择时研究”
- 指数 / ETF 的数据连续性、信号稳定性通常比单只股票更适合先跑通流程

如果你是第一次上手，优先使用：

```text
symbol = sh000300
start  = 2025-01-01
end    = 今天
forward_period = 5
```

## 6. 研究页能做什么

研究页目前分成三块。

### 6.1 因子库

功能：

- 展示系统支持的可用因子
- 帮你确认某个因子是否真的在当前版本里存在

当前因子大致分为五类：

- 趋势：`ma_*`、`ema_*`、`macd_*`、`adx`
- 动量：`rsi_14`、`roc_*`、`cci`
- 波动率：`bb_*`、`atr`、`rvol_*`
- 成交量：`obv`、`vwap`、`volume_ratio`
- 价格结构：`ret_*`、`log_ret`、`hl_range`、`co_range`

### 6.2 因子计算与评估

功能：

- 查询已持久化因子
- 计算全因子
- 评估因子
- 做 Walk-Forward

### 6.3 标签预览与特征筛选

功能：

- 生成未来收益方向标签
- 查看末尾截断情况
- 输出特征筛选报告

## 7. 推荐实操流程

建议严格按下面顺序做，不要一上来就直接训练模型。

### 第一步：查询是否已经算过因子

研究页点击：

- `查询`

对应接口：

```http
GET /api/v1/factors/values/{symbol}
```

你应该关注：

- 当前区间是否已有已持久化因子
- `交易日数`
- `因子数`
- 已覆盖的最小日期和最大日期

如果这里没有结果，说明还没算过，继续第二步。

### 第二步：计算因子

研究页点击：

- `计算因子`

对应接口：

```http
POST /api/v1/factors/batch-compute
```

示例请求：

```json
{
  "symbol": "sh000300",
  "start": "2025-01-01",
  "end": "2026-04-12",
  "persist": true
}
```

你应该关注：

- `rows`：成功计算了多少个交易日
- `factors`：实际生成了多少个因子列
- `data_start / data_end`：真正参与计算的数据区间
- `sample`：最近几行样本是否有值

判断标准：

- `rows` 很小，通常说明底层日线数据不够
- `factors` 明显偏少，可能说明因子库或数据列异常
- 样本全是空值，通常是原始行情数据异常或时间区间过短

### 第三步：评估因子

研究页点击：

- `评估因子`

对应接口：

```http
POST /api/v1/factors/evaluate
```

示例请求：

```json
{
  "symbol": "sh000300",
  "forward_period": 5,
  "start": "2025-01-01",
  "end": "2026-04-12",
  "persist": true
}
```

你应该重点看这些指标：

- `IC Mean`
- `ICIR`
- `Rank IC`
- `Rank ICIR`
- `IC+%`
- `单调性`

可用的直觉判断：

- `IC Mean` 绝对值越大越好，但更看稳定性
- `ICIR` 越高越说明因子稳定
- `IC+%` 越高越说明因子在更多子区间里方向一致
- `单调性` 越高越说明因子分层效果更清晰

当前阶段建议重点挑出：

- `|IC Mean|` 靠前的因子
- `ICIR` 不太差的因子
- `IC+%` 不是纯随机的因子

如果一个因子只在某一段特别强，但整体 `ICIR` 很差，不建议直接送去建模。

### 第四步：做 Walk-Forward

研究页点击：

- `Walk-Forward`

对应接口：

```http
POST /api/v1/factors/walk-forward
```

默认思路是滚动窗口验证：

- 训练窗：`120`
- 测试窗：`20`
- 步长：`20`

示例请求：

```json
{
  "symbol": "sh000300",
  "train_days": 120,
  "test_days": 20,
  "step_days": 20,
  "forward_period": 5,
  "start": "2025-01-01"
}
```

你应该关注：

- 同一个因子在多个 fold 上是否都能维持接近方向
- `Avg Test IC`
- `Avg Return`
- `Avg Sharpe`
- `IC 一致性`

判断原则：

- 样本内强、样本外弱的因子，不要太早相信
- 若多个 fold 符号来回翻转，说明稳定性不足
- Walk-Forward 的作用不是找“单次最高收益”，而是筛“可复用的因子”

### 第五步：生成标签

研究页点击：

- `生成标签`

对应接口：

```http
POST /api/v1/ml/labels
```

默认会生成：

- `fwd_ret_5 / 10 / 20`
- `label_dir_5 / 10 / 20`

你应该关注：

- `valid_rows`
- `truncated_tail`
- `full_invalid_tail`
- `nan_per_period`
- `valid_end`

这里有一个很重要的当前实现细节：

- 标签会因为“未来 N 天收益不可见”而在尾部出现 `NaN`
- 这些尾部样本不会参与训练和 GP 挖掘

这属于正常现象，不是 bug。

### 第六步：特征筛选

研究页点击：

- `特征筛选`

对应接口：

```http
POST /api/v1/ml/feature-select
```

当前筛选流程是三段式：

1. 方差过滤
2. 高相关去重
3. 按与标签的 IC 绝对值做排序

后端当前默认阈值：

- `variance_threshold = 1e-6`
- `correlation_threshold = 0.95`

你应该关注：

- `original_count`
- `after_variance`
- `after_correlation`
- `final_count`
- `dropped_variance`
- `dropped_correlation`
- `feature_ranking`

怎么看结果：

- 如果 `original_count` 很多，但 `final_count` 极少，说明特征冗余很强或数据问题较大
- 如果大量因子因高相关被删，这是正常的
- `feature_ranking` 可以直接作为去模型页前的候选特征参考

## 8. 建议你这样判断研究结果是否“值得继续”

当前项目阶段下，可以用一个简单标准做 go / no-go 决策。

适合继续去模型页的情况：

- 因子计算正常，样本覆盖足够长
- 因子评估里至少能挑出几组相对稳定的因子
- Walk-Forward 结果不是全面失真
- 特征筛选后仍保留一批有效特征

不建议继续建模的情况：

- 因子评估普遍接近 0
- Walk-Forward 多数因子样本外反复翻转
- 标签有效样本过少
- 筛选后几乎没剩特征

如果研究阶段都站不住，直接训练模型大概率只是“把噪声复杂化”。

## 9. 推荐的研究参数模板

### 9.1 指数 / ETF 基础模板

适合第一次跑通：

```text
symbol = sh000300
start = 2025-01-01
end = 今天
forward_period = 5
train_days = 120
test_days = 20
step_days = 20
```

### 9.2 更稳一点的样本模板

适合准备进入模型训练：

```text
symbol = sh000300
start = 2024-01-01
end = 今天
forward_period = 5
train_days = 200
test_days = 20
step_days = 20
```

说明：

- 如果时间太短，标签和 Walk-Forward 都会变得不稳定
- 当前 `Pipeline` 至少希望有 `100` 行以上数据
- 训练/测试切分最好保证训练集不少于 `60` 行，测试集不少于 `20` 行

## 10. 与模型板块如何衔接

研究页做完后，建议这样衔接到模型页。

### 推荐路径 A：稳妥路线

1. 研究页算因子
2. 研究页评估因子
3. 研究页做特征筛选
4. 模型页训练 `LightGBM`
5. 模型页做 `Walk-Forward`
6. 模型页看最新信号

### 推荐路径 B：快速路线

1. 确认数据够长
2. 直接去模型页运行 `Pipeline`

适合场景：

- 你已经知道这个标的研究基础不错
- 你想快速看 end-to-end 结果

不适合场景：

- 你还没验证因子是否有效
- 你正在定位数据或研究问题

## 11. 常见问题与排查

### 11.1 研究页点了没结果

优先检查：

1. 服务是否真的启动
2. 标的是否已有日线数据
3. `start` / `end` 是否填反
4. 该标的在当前数据源下是否可用

### 11.2 因子计算失败或结果很少

常见原因：

- 原始行情数据太短
- 数据时间区间太窄
- 某些指标需要回看窗口，前部会自然丢掉一段

### 11.3 标签最后几天是空的

这是正常行为。

原因：

- 未来 `N` 天收益还不可知
- 比如 `label_dir_20`，最后 20 天天然无法构造完整标签

### 11.4 特征筛选后几乎没有特征

常见原因：

- 因子之间强相关
- 标签有效样本不足
- 所选区间过短，统计不稳定

### 11.5 因子评估还可以，但模型效果差

这是很常见的。

说明：

- 单因子有一定预测力，不代表组合建模一定有效
- 模型过拟合、样本切分、标签噪声都可能让模型表现变差

这时应该先回看：

- Walk-Forward 是否稳定
- 标签定义是否合适
- 时间区间是否过短

## 12. 最小可执行研究清单

如果你只想照着做一次，按下面这份 checklist 即可。

### 前置

- 启动后端
- 补齐 `sh000300` 日线
- 打开 Web UI 的 `研究` 页

### 执行

1. 输入：
   `symbol = sh000300`
2. 输入：
   `start = 2025-01-01`
3. 点击：
   `查询`
4. 若无结果，点击：
   `计算因子`
5. 点击：
   `评估因子`
6. 点击：
   `Walk-Forward`
7. 点击：
   `生成标签`
8. 点击：
   `特征筛选`

### 判断

- 如果结果整体正常，再去 `模型` 页训练 `LightGBM`
- 如果评估和 Walk-Forward 很差，先不要急着训练模型

## 13. 对当前项目的使用建议

结合当前项目现状，我建议你把研究板块当成“模型训练前的门禁”。

更具体地说：

- 先用研究页筛掉明显无效的时间区间和标的
- 再把较稳定的标的送到模型页
- 优先做指数 / ETF，不要一开始就分散到大量个股
- 优先固定一套参数模板，把流程跑稳定，再做参数试验

如果你后面准备把这套流程常态化，建议下一步补两类文档：

1. “模型板块实操手册”
2. “从研究到回测的一体化日常流程”
